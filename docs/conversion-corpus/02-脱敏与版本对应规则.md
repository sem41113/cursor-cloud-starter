# 脱敏与版本对应规则

目标：自建转换读到的源文件，和店内 Word/WPS 打印对照，是脱敏之后的同一个版本。

## 固定顺序

同一份样本只按这个顺序做。

1. 把客户原件复制到店内隔离目录。隔离目录不同步网盘，不上传。
2. 在原件的副本上脱敏。不要在客户唯一原件上直接改。
3. 用 Word 或 WPS 保存脱敏结果。保存之后立刻计算 SHA-256。这个摘要记为 `source_sha256`，版本记为 `v1`。
4. 不要关闭后用别的软件打开。立刻用刚刚保存的这份文件，在这台店内电脑上打印对照。本准备选择的形式是打印到 PDF，这项选择尚未确认。环境表写明软件名称、完整版本和打印设置。
5. 计算对照 PDF 的 SHA-256，记为 `reference_sha256`。
6. 填写环境与对照表，把两个摘要、软件版本、打印设置、页数，以及「对照由哪一次保存立即打印」写上。
7. 封存该目录。之后只复制，不再修改目录里的源文件和对照 PDF。

客户原件在封存完成后从隔离目录删除。样本包里只保留脱敏文件。

## 什么必须换掉

- 姓名、手机号、身份证号、地址、邮箱、银行卡号、微信号、学号工号。
- 真实单位名称、文号、项目名称、合同编号。
- 公章、签名、证件照片、人脸照片。
- 未公开的金额、成绩、账号和诊断信息。

替换时保持版式：

- 文字换成相近长度的占位。姓名可以用「甲某」「乙某」。号码用相同位数的明显虚构数字。
- 不改字体、字号、段落样式、分节、页眉页脚、表格结构和环绕方式。
- 图片换成相同像素尺寸的灰块，环境表写「图片已替换，尺寸未改」。灰块造成版式变化时，以变化后的文件重新打印对照。
- 公章和签名删除后，以删除后的文件重新打印对照。
- 脱敏后不要更新目录域、交叉引用和日期域。更新域会改变页数，使对照不再代表客户当时的文件。

## 什么不要放进样本包

- 真名与占位的映射表。店内如果必须留存，单独离线保管，不随样本交接。
- 客户原文件名、微信聊天记录截图、订单信息。
- 未脱敏的原件。

交接前在脱敏文件中搜索已经见过的手机号、证件号和单位名称。发现残留则继续脱敏，并因此升版本。

## 版本规则

版本号写成 `v1`、`v2`。下列任一情况都要升版本：

- 脱敏后又改了一个字、一张图或一个样式。
- 重新保存。
- 换了一台电脑、一个 Word/WPS 版本或一套打印设置重新导出对照。

升版本时：

1. 新的源文件摘要成为新的 `source_sha256`。
2. 旧的对照 PDF 作废，不留在样本目录里。
3. 用新源文件重新打印，产生新的 `reference_sha256`。
4. 环境表保留旧版本号和作废原因，测试只使用最新版本。
5. 已交给测试的旧版本若已经转换，旧运行结果保留，但不得和新版本混在同一次汇总里。

没有「只换对照、不升版本」。对照 PDF 只能从当前 `source_sha256` 打印出来。

## 接收方核对什么

收到目录后，在不打开编辑器的前提下重新计算两个 SHA-256。

摘要一致只说明交接之后的文件与登记字节相同，没有在途中被改动。它不能单独证明对照 PDF 是由该源文件打印出来的。打印关系靠店内生成和登记：脱敏后立即打印，环境表写明软件、版本、打印设置和这次封存顺序。

- 两个摘要都与环境表一致，并且生成登记齐全：接收检查的这项通过。
- 摘要一致，但缺少软件版本或打印设置：整份退回。
- 任一摘要不一致：整份退回。不在接收方修改文件来凑摘要。
- 环境表缺少任一摘要：整份退回。
- 源文件打不开、提示修复，或要求打开密码：整份退回，不当作 R 样本。不要先让 LibreOffice 修复或解密再当作客户源文件。打开密码的拒绝测试只接收单独编号的 X 样本。

接收方不补打印对照，也不重新脱敏。这两件事只在产生源文件的那台店内电脑上做。
