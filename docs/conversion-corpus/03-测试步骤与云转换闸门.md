# 自建测试步骤与备用云转换闸门

本文件是收到样本之后才执行的步骤。现在样本数为 0，所以这里的步骤都还没有执行。

默认转换器按已确认决策使用自建转换。本次正式运行的转换器是 LibreOffice，运行在无外网、限时、限内存、每次独立配置目录的环境中。这是报告 B.1 的原文要求，与已确认的「默认自建」一致。

OnlyOffice 是否同时跑一轮对照，报告建议纳入，产品负责人尚未确认。未确认前，正式汇总只统计 LibreOffice。

## 接收样本后的第一步：接收检查

第一步不是转换，也不是上传。

对交出的每个编号做下面的检查。全部通过，收集状态才能从「已封存」改为「已接收」。

- [ ] 目录含源文件、对照 PDF、环境表。
- [ ] 源文件是 DOC 或 DOCX，文件名不含客户原名。
- [ ] 重新计算的 SHA-256 与环境表一致。
- [ ] 环境表写明 Word 或 WPS 的完整版本、操作系统、纸张、100% 实际大小、批注和修订的打印选择。
- [ ] 对照 PDF 来自该源文件的当前版本，不是 LibreOffice 导出的。
- [ ] 主类别对应收集清单中的一个已填名额，编号没有被合成文件占用。
- [ ] 环境表确认样本包内没有真名映射表。
- [ ] 文件可以直接打开，不需要打开密码。

任一失败：状态改为「已退回」，写明原因，不转换。

全部交件检查完之后，统计七个核心类是否都达到清单中的最少份数。未达到时，可以先把已接收文件放着，不开始正式汇总。产品负责人书面豁免某一类之后，才允许在缺类的情况下汇总。

## 正式运行前冻结环境

同一次正式运行使用同一套转换环境。开始前记录到运行单，开始后不再安装字体、不再升级 LibreOffice。

- 运行编号：`CONV-RUN-` 加日期和两位序号。
- LibreOffice 的完整版本。
- 容器或机器镜像标识。
- 已安装字体清单。不把 Windows 自带字体复制到 Linux 上凑结果；字体授权仍待确认。
- 确认该环境没有外网。
- 超时和内存上限。报告要求限制，但没有给数值。在产品负责人确认前，执行时暂时使用 120 秒和 2 GB，并在运行单上标明这是未确认的执行参数。

## 自建转换

对每个已接收编号：

1. 新建空的临时配置目录。转换结束即删除，不在多个样本之间复用。
2. 用冻结好的 LibreOffice 把源文件转为 PDF。记录退出码、耗时、失败信息。
3. 超时或崩溃只原样重试一次。第二次仍失败，结果记为「转换失败」，归因代码 `FAIL`。不要换转换器重试。
4. 保留 LibreOffice 直接输出的 PDF，计算 SHA-256。
5. 按报告 B.2 做规范化，形成「确认版候选 PDF」：修复结构、去掉权限密码、拍平表单和批注、记录每一页的尺寸和旋转、计算 SHA-256。需要打开密码的文件记为拒绝，不进入页数比较。
6. 解析 DOCX 字体表。字体未安装在转换环境时，记入该文件结果，作为缺字体提示的依据。DOC 的字体表可能不完整，结果里要注明。
7. 分别记录直接输出 PDF 的页数和候选 PDF 的页数。两者不同时，两个页数都保留。与店内对照比较时，以候选 PDF 为准，因为报告 B.2 规定用户确认和打印都基于规范化 PDF。

候选 PDF、直接输出 PDF 和日志放在仓库以外的运行目录。不要覆盖源文件和对照 PDF。

## 逐页对照

每一份都做，不抽查。

1. 页数：候选 PDF 页数与对照 PDF 页数。相等记「页数一致」，否则记「页数不一致」。
2. 页面尺寸和旋转：逐页记录对照与候选是否同为横向或纵向。
3. 像素：页数一致时，双方都以 100 DPI 渲染为灰度图，记录每一页的差异像素占比。页数不一致时，只对双方都存在的页码做渲染，并在结果中写明无法逐页对齐。100 DPI 和差异占比只用于找出需要目检的页面。报告 E.6 要求比较像素，但没有规定差值多少算通过。不得用某个像素百分比直接宣布样本通过。
4. 人工目检：打开对照 PDF 和候选 PDF。至少查看首页、末页、每一个差异像素占比高的页面、每一页含表格、浮动图、文本框、页眉或横向设置的页面。结论只使用三档：通过、有轻微差异、有重大版式问题。
5. 目检人在逐文件记录上签名并写日期。转换执行人可以和目检人是同一人，汇总时要注明。

重大版式问题和轻微差异的定义见 [05-验收标准与记录模板.md](05-验收标准与记录模板.md)。该定义尚未经产品负责人确认，记录时照此填写，汇总时标明「按待确认定义统计」。

## 问题归因

每份样本选择一个主因。可以附加次因。主因使用下面的代码。

| 代码 | 含义 |
|---|---|
| FONT | 缺字体或字体替换导致重排、溢出、不可读 |
| TABLE | 表格错位、合并单元格丢失、跨页标题丢失 |
| FLOAT | 浮动图、文本框、形状错位、丢失或遮挡正文 |
| HEADER | 页眉、页脚、页码或分节丢失、串节 |
| ORIENT | 页面方向、纸张或页边距错误 |
| FIELD | 目录、交叉引用、日期域、页码域变化 |
| NOTE | 批注、修订、脚注、尾注的显示与对照不同 |
| IMAGE | 图片丢失、变形，或替换灰块未被如实保留 |
| BREAK | 文字还在，但分页位置变化 |
| FAIL | 转换失败、超时、崩溃，或因打开密码被拒绝 |
| OTHER | 以上都不是。写一句话说明 |

页数不一致时，主因按造成分页变化的最明显原因填写。看不出原因时用 `BREAK`，不要猜成 `FONT`。

## 复测

复测不改变真实样本的份数，也不替换旧记录。

- 新的运行编号。
- 每次只改变一个因素：安装一种已授权字体、升级一次 LibreOffice，或改变一个导出设置。
- 运行单写明改变了什么。
- 旧运行的逐文件记录保留。
- 进入正式汇总的是哪一次运行，由记录人在汇总模板指定。默认使用第一次完整跑完已接收样本的运行。用复测结果替换默认运行，需要在汇总里说明原因。

升级 LibreOffice 或字体之后，报告 E.6 要求重跑语料。复测就是这项要求的执行方式。

## 汇总决策

汇总使用 [templates/汇总记录.md](templates/汇总记录.md)，只统计状态为「已接收」且属于指定正式运行的真实样本。

必须同时写出三个数：

- 页数一致率 = 页数一致的份数 / 纳入汇总的真实样本份数。
- 人工目检通过率 = 目检结论为「通过」的份数 / 已完成目检的真实样本份数。「有轻微差异」不计入通过。
- 重大版式问题 = 结论为「有重大版式问题」的份数，以及它占纳入汇总份数的比例。转换失败按重大版式问题计，并同时在失败栏单列。

分母不含：合成样本、已退回样本、未接收样本、产品负责人书面豁免因而未收集的名额。豁免减少的是应收集名额，不制造一个通过结果。

汇总的决策栏固定写两句已确认事实：

1. 默认转换器维持自建。
2. 本次比率不自动把第三方云转换改成默认。报告 B.1 关于「低于 95% 则默认云端」的建议不被执行。

95% 只放在「待确认门槛」栏，旁边填写实际页数一致率，供产品负责人以后判断。准备阶段不填写「达到门槛」或「未达到门槛」。

汇总还可以给出备用云转换是否值得继续核价的观察，例如某一类主因集中且自建字体无法合法补齐。观察不是启用决定。启用必须走过下面的闸门。

## 第三方备用转换的闸门

当前停在 G0。本次真实样本测试不调用云转换，不上传文件。

| 闸门 | 条件 | 当前 |
|---|---|---|
| G0 禁止调用 | 样本测试的正式运行只用自建转换 | 生效 |
| G1 正式报价 | 选定一家服务商，归档其官方报价。报告中的 WPS 开放平台和腾讯云数据万象仍只是备选，尚未选定 | 未做 |
